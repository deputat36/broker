# Полный аудит сайта и автономный план улучшений

Дата актуализации: 2026-09-07.

Репозиторий: `deputat36/broker`.

Основной домен: `https://sterlikova-ipoteka.ru/`.

Центральный roadmap: issue #5.

## 1. Итог аудита

Сайт уже является полноценной контентной и конверсионной системой ипотечного брокера, а не одностраничным лендингом. В проекте работают услуги, региональные кластеры, полезные материалы, калькулятор, онлайн-заявка, контакты, стоимость, консультация, FAQ, политика, Schema.org, Open Graph, sitemap, robots, PWA-метаданные, мобильные сценарии и многоуровневый CI-аудит.

Главная задача текущего этапа — не наращивать URL ради количества, а повышать качество существующего сайта:

1. удерживать CI и production-smoke полностью зелёными;
2. сохранять запас performance budget;
3. улучшать самые слабые материалы по глубине и перелинковке;
4. не допускать неподтверждённых банковских и коммерческих обещаний;
5. подключить внешние системы аналитики и индексации после получения необходимых доступов;
6. принять реальный Web3Forms-канал тестовой заявкой;
7. переводить Supabase в production только после отдельной приёмки.

Performance после оптимизации онлайн-заявки в run #1256:

- общий вес файлов: 2 768 763 байта;
- CSS: 50 414 байт;
- JS: 84 039 байт;
- изображения: 48 433 байта;

## 5. Автономный план

### Этап A. Стабильность — поддерживать постоянно

- [x] Полный source-audit.
- [x] Полный post-build audit.
- [x] GitHub Pages deploy.
- [x] Production-smoke.
- [x] Performance budget.
- [x] Privacy/security контракты.
- [x] Контентные и SEO-аудиты.
- [ ] После каждого изменения не оставлять `main` с красным обязательным workflow.

### Этап B. Performance

1. Увеличить запас `/online-zayavka/` относительно 170 KB.
2. Не повышать лимит без объективной причины.
3. Не вырезать privacy, fallback, согласие и доступность ради веса.
4. Искать условно загружаемые или повторяющиеся ресурсы.
5. Следить за общей JS-суммой, которая близка к текущему лимиту.

### Этап C. Контент и SEO

1. Использовать новый рейтинг content-audit.
2. Сначала улучшать самые короткие статьи и страницы с минимальной перелинковкой.
3. Добавлять практическую ценность, а не SEO-воду.
4. Усиливать переходы на релевантные услуги, калькулятор и онлайн-заявку.
5. Не создавать новую страницу, если тема уже закрывается существующей.
6. Не публиковать текущие ставки, лимиты и условия программ без актуальной проверки.

### Этап D. Конверсия

1. Сохранять короткий путь к онлайн-заявке и телефону.
2. Улучшать contextual CTA по исходной странице и сценарию.
3. Проверять mobile UX после крупных изменений.
4. Не хранить телефон, имя и финансовые данные клиента в browser storage.
5. После подключения Метрики проверять реальную воронку, а не гадать по дизайну.

### Этап E. Внешняя приёмка

Требует данных или действий вне репозитория:

- ID Яндекс Метрики;
- Яндекс Вебмастер;
- Google Search Console;
- реальный Web3Forms smoke и подтверждение email;
- social preview в ВК/мессенджерах;
- живой Supabase rollout;
- production secrets и политика хранения данных.

## 6. Правила автономной работы

Можно делать без дополнительных вопросов:

- исправлять технические ошибки и красный CI;
- оптимизировать производительность без ослабления бюджетов;
- улучшать доступность и mobile UX;
- усиливать существующий контент и перелинковку;
- улучшать Schema.org, sitemap, robots и документацию;
- поддерживать privacy и security audits;
- убирать устаревшие технические формулировки;
- проверять опасные ипотечные обещания.

Нельзя делать без подтверждения:

- придумывать тарифы и условия «ЭТАЖИ»;
- публиковать отзывы, кейсы или персональные достижения;
- обещать одобрение, конкретные ставки или гарантированные сроки;
- менять production-получателя Web3Forms без smoke;
- включать Supabase/hybrid delivery без живой приёмки;
- добавлять реальные банковские условия без актуальной проверки.
