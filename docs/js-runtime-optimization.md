# Оптимизация JavaScript runtime

Дата baseline: 8 сентября 2026 года.

## Текущий бюджет

CI ограничивает общий JavaScript Pages-артефакта значением `85 000` байт.

Подтвержденный baseline workflow #1288:

- общий JS: `84 039` байт;
- свободный запас: `961` байт;
- максимальный отдельный JS-файл: `32 000` байт;
- `/online-zayavka/`: `166 533` байта локальной загрузки при лимите `170 000`.

Повышать эти лимиты вместо оптимизации нельзя.

## Состав JavaScript

### Глобальный runtime

- `main.js` — навигация, контакты, аналитика и общие улучшения интерфейса.

### Калькулятор

- `mortgage-calculator.js`;
- `calculator-application-prefill.js`;
- `calculator-application-prefill-runtime.js`.

Prefill уже разделен на легкий bootstrap и условный runtime.

### Онлайн-заявка

- `application-delivery-keepalive.js`;
- `application-inputs.js`;
- `application-preparation.js`;
- `online-application.js`.

Эти модули нужны только маршруту `/online-zayavka/` и не должны становиться глобальными.

### Страница благодарности

- `thankyou-storage-privacy.js`.

## Почему простое разбиение `online-application.js` не решает лимит

Performance-аудит считает общий размер всех `.js` в Pages-артефакте. Если один файл разбить на два без уменьшения кода, общий JS останется практически тем же.

Runtime-split имеет смысл только для уменьшения first-load конкретной страницы. Он не должен использоваться как способ обойти общий бюджет.

## Правильный порядок оптимизации

1. Сначала измерить состав JS и найти реальное дублирование или код, который больше не нужен.
2. Сохранить общий лимит `85 000` байт.
3. Не добавлять новый модуль без явной классификации в `scripts/audit-js-composition.py`.
4. Если delivery-логику выносить из `online-application.js`, загружать ее только тогда, когда пользователь подготовил валидную заявку или непосредственно перед онлайн-отправкой.
5. До изменения runtime проверить контракты текущих аудитов формы, privacy, fallback, Web3Forms и hybrid delivery.
6. После изменения обязательны green source-audit, build, deploy и production-smoke.

## Что нельзя потерять при оптимизации формы

- короткий обязательный сценарий формы;
- нормализацию российского телефона;
- honeypot и минимальное время заполнения;
- `request_id`;
- source/scenario/placement и UTM-атрибуцию;
- безопасный Web3Forms payload;
- будущий hybrid/Supabase payload;
- timeout и обработку ошибок;
- fallback через SMS, MAX, ВКонтакте, Web Share и копирование;
- privacy-safe `/spasibo/`;
- цели аналитики;
- отсутствие контактных данных в browser storage.

## Автоматический контроль

`scripts/audit-js-composition.py`:

- читает лимиты из `scripts/performance-budget.json`;
- контролирует общий исходный вес JS;
- контролирует максимальный размер отдельного файла;
- требует явной классификации каждого браузерного JS-модуля;
- выводит вес по группам `global`, `calculator`, `application`, `thankyou`.

Таким образом новый JS не может появиться незаметно: изменение состава требует отдельного осознанного изменения аудита.
